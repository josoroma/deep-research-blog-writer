Overview

Setup

You need Git, uv, and Make. uv installs Python 3.12 from .python-version. The CLI needs no server; the API path also needs Docker for PostgreSQL.

  1. make setup installs the locked dependencies from uv.lock and the Git hook.
  2. make check runs the lock check, Ruff, the format check, mypy in strict mode, and the offline tests with an 80% coverage floor. Sockets are blocked and no key is needed.
  3. cp -n .env.example .env, then fill in the values below. .env is git-ignored.
Settings a live run reads from .env

SERPAPI_API_KEYSearchSet SEARCH_PROVIDER=serpapi. Serper uses its own key, and the two never fall back to each other.
OPENROUTER_API_KEYSearch planning, authoringAll five agents default to openrouter:deepseek/deepseek-v4.1-flash.

SEARCH_TIMEOUT_SECONDSSearchDefaults to 15. The example run used 60, because the first uncached query timed out.
Exit statuses of the phase commands
ExitMeaning
0The phase completed.
1The phase ran and failed. Its summary JSON says why.
2Input or configuration was rejected before any work started, such as a missing key, --per-page other than 10 on SerpApi, or a missing workspace.

API and worker

The HTTP API only admits and reads. A separate worker claims the job, runs the shared use cases, and writes the workspace. Importing api starts no worker and calls no provider.

Start it on one machine

  1. make api-up starts PostgreSQL 17 on 127.0.0.1:5432. The user, password, and database are all research. make api-down stops it and keeps the volume.
  2. Export API_DATABASE=postgresql://research:research@127.0.0.1:5432/research, then run make migrate-api. It is idempotent: the first run printed Applied 1 migration(s); checkpoint schema is ready. and the second printed Applied 0 migration(s). It creates jobs, schema_migrations, and four LangGraph checkpoint* tables.
  3. make run-api serves on 127.0.0.1:8000. In a second terminal with the same API_DATABASE, run make worker-api. Set API_RUN_PROFILE=fixture for both to run the stack with no model, search, or website calls.

Resume does not check that the workspace exists

In a second test the job recorded a run id, but its directory was never created. Resume still returned 202, because it only checks the job state. The worker then failed the job with error: ValueError on attempt 2.

The CLI --resume flag only prints the next phase. Continuing a run is POST /v1/runs/<run_id>/resume followed by a worker attempt.

The run loop

No single command runs the whole pipeline. You run three phase commands in order, each against the workspace the previous one wrote. Two of the phases loop internally, and a failed search sends you back to the start.

  1. SEARCH_TIMEOUT_SECONDS=60 uv run deep-research-blog "Python LangChain Deep Agents Startup Ideas" --search-only --pages 3 --per-page 10 --max-urls 30
  2. RUN=runs/python-langchain-deep-agents-startup-ideas-20261001T195605Z, then uv run deep-research-blog --corpus-only --workspace "$RUN"
  3. uv run deep-research-blog --author-only --workspace "$RUN"

Which command runs which phase

Search

The planner calls the model once to derive query variants, and it gets two attempts to produce a valid plan. The provider calls follow a fixed merge order, then normalization filters and caps the results.

Authoring and the citation gate

Two model calls write the summary and the draft. A deterministic gate then checks the citations and can send the writer back for up to two repair passes. The draft is never regenerated for length.

What the draft drew on

The draft is titled "Python LangChain Deep Agents Startup Ideas: Building on the Harness, Not the Model". After the title, its headings follow the required order: Introduction, Landscape, Key Frameworks, Analysis and Trade-offs, Outlook, Conclusion, References.

Outcome and retries

EPIC-8 added the run-level outcome rules, a retry-once wrapper, and resume. They are implemented and tested but not yet wired into the three phase commands (see What is not wired yet).

Retry once, then fail

  • Resume. --resume <run_id> reads the newest saved state (corpus_state.json, then fetch_state.json, then search_state.json) and prints the first phase not yet completed. For the example, that is synthesize. It exits 0 and does not continue the run. An unknown run id exits 2.
  • Checkpoints. A per-run SQLite checkpointer at runs/<run_id>/checkpoints.sqlite, with the run id as the thread id (ADR 0007). It is exercised by the EPIC-8 demo.

Workspace layout

Each run gets its own directory, named from the topic plus a UTC timestamp. Each command writes its own files and reads the files the previous command wrote.

Why runs.example/ is committed

runs/ is git-ignored, so a fresh run is never committed. runs.example/ is a saved copy of the three commands' output that anyone with a checkout can open.

Observability and service URLs

Every run writes logs/execution.log and logs/telemetry.json into its workspace. Metrics go to a local Grafana stack and traces go to hosted LangSmith; both are opt-in.

  1. make observability-up starts the OpenTelemetry collector, Prometheus, and Grafana from ops/observability/compose.yaml. Every port is bound to 127.0.0.1.
  2. make demo-epic-9 runs the agent hierarchy offline, exports real OTLP metrics, and prints a run id. make smoke-epic-9 checks that Prometheus and Grafana received them.
  3. For hosted traces, set LANGSMITH_TRACING=true and LANGSMITH_API_KEY in .env, then run make smoke-langsmith.
  4. make observability-down stops the stack. The named volumes keep the history.

What is not wired yet

  • The plain command, run with a topic and no phase flag, invokes the agent skeleton. Its downstream tools are still named stubs, so a completed status there does not mean a finished blog.
  • No console command writes the EPIC-8 run report. The output/run.json from --author-only is the citation-gate record.
  • Exit 3 (degraded) belongs to that report, so the phase commands only ever return 0, 1, or 2.
  • --resume prints the phase it would restart at. It does not continue the run.
  • The retry-once wrapper and the SQLite checkpointer are used by the report workflow and the EPIC-8 demo, not by the three phase commands. The worker resumes an interrupted job from the last completed phase through POST /v1/runs/<run_id>/resume.
  • The API and worker have run end to end against real PostgreSQL, but only with fixture providers. A server run with live models and search is still pending.
  • One worker runs one job at a time. Raising concurrency needs shared crawler rate limits first.
  • The citation gate checks that each citation exists and that its title and URL match. It does not check whether a source is on topic.
  • Traces and metrics are opt-in. LangSmith needs LANGSMITH_TRACING=true and a key; metrics export needs OTEL_EXPORTER_OTLP_ENDPOINT. With both unset, a run still writes its local logs.
